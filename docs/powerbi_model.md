# Power BI model: build guide

Everything below already exists in `WWI_Analytics` (gold schema). Power BI only imports and visualises.
Connect: **Get data → SQL Server → Server `localhost`, Database `WWI_Analytics`, Data connectivity: Import**
(use your Windows login, or the least-privilege `wwi_etl` login from `sql/00_setup/03_create_etl_user.sql`).

## 0. As built

The sections below are the original build guide; the report as finally built differs in these points:

- **Format:** Power BI Project (`powerbi/WWI_Planning.pbip`, PBIR report + TMDL model). Report pages are generated by `powerbi/build_report.py` (edit the spec → run the script → *Apply external changes* in Desktop). `WWI_Planning.pbix` is a copy with data.
- **Tables (20):** the 17 listed below (Stock Item comes from `gold.vw_pbi_stock_item`; Demand Monthly was not needed) plus `Robustness` (`gold.robustness_result`, with DAX text columns `metric_label`, `value_text`, `ci_95_text`), `Policy Monthly` (`gold.vw_policy_kpi_monthly`, → Scenario) and `Forecast Accuracy Monthly` (`gold.vw_forecast_accuracy_monthly`).
- **Relationships:** 19 (the list below + Scenario KPI → Scenario, Lead Time Audit / Backorder by SKU → Stock Item, Policy Monthly → Scenario).
- **Measures:** 25 = `powerbi/measures.dax` (24) + `Target SL Value` from the what-if parameter. Same-period YoY measures replace the calculation group: a calculation group turns off implicit measures, and several visuals use column aggregations.
- **Calculated column:** `'DQ Results'[is_latest_run]`: the Data-quality page filters on it, so no run id is hard-coded. Scenario filters use attributes (`target_type = "CSL"`, `service_level = 0.95`), not ids.
- **Pages (8):** 1 S&OP overview · 2 Demand & forecast · 3 Policy simulation · 4 Planning-parameter audit · 5 Customer service · 6 Data quality & ETL · 7 Robustness checks · 8 SKU detail (drill-through on `'Stock Item'[stock_item_name]`, reachable from the SKU tables on pages 4 and 5).
- **RLS:** role `Clothing planner`, filter `'Stock Item'[primary_stock_group] = "Clothing"`: tested: 74 of 227 SKUs, 2.84M of 9.31M units, $46.4M of $172.3M revenue.

## 2. Relationships (single direction, many → one)

- Order Line[order_date_key] → Date[date_key]; Order Line[stock_item_id] → Stock Item; Order Line[customer_id] → Customer
- Invoice Line[invoice_date_key] → Date[date_key]; Invoice Line[stock_item_id] → Stock Item; Invoice Line[customer_id] → Customer
- Simulation[date_key] → Date[date_key]; Simulation[stock_item_id] → Stock Item; Simulation[scenario_id] → Scenario
- Policy Parameters[stock_item_id] → Stock Item; Policy Parameters[scenario_id] → Scenario; Policy Parameters[month_start] → Date[date]
- Demand Monthly[month_key] → Date[date_key]; Forecast[month_start] → Date[date]; Forecast[stock_item_id] → Stock Item
- Service Monthly[month_start] → Date[date]

## 3. DAX measures

```DAX
-- Sales & service (actuals)
Revenue = SUM ( 'Invoice Line'[revenue_excl_tax] )
Gross Margin % = DIVIDE ( SUM ( 'Invoice Line'[line_profit] ), [Revenue] )
Units Ordered = SUM ( 'Order Line'[quantity] )
Unit Fill Rate = DIVIDE ( SUM ( 'Order Line'[picked_quantity] ), [Units Ordered] )
Backorder Unit Share =
    DIVIDE ( CALCULATE ( [Units Ordered], 'Order Line'[is_backorder_line] = 1 ), [Units Ordered] )
On-Time Delivery % =
    DIVIDE (
        CALCULATE ( DISTINCTCOUNT ( 'Invoice Line'[invoice_id] ), 'Invoice Line'[is_on_time] = 1 ),
        CALCULATE ( DISTINCTCOUNT ( 'Invoice Line'[invoice_id] ), NOT ISBLANK ( 'Invoice Line'[is_on_time] ) )
    )

-- Forecast
Forecast Units = SUM ( Forecast[forecast_units] )
Actual Units (fc) = SUM ( Forecast[actual_units] )
WAPE = DIVIDE ( SUM ( Forecast[abs_error_units] ), [Actual Units (fc)] )
Forecast Bias = DIVIDE ( SUM ( Forecast[error_units] ), [Actual Units (fc)] )

-- Simulation (always filter one Scenario, or put Scenario on an axis)
Sim Fill Rate = DIVIDE ( SUM ( Simulation[filled_qty] ), SUM ( Simulation[demand_qty] ) )
Sim Avg Inventory Value =
    SUMX (
        VALUES ( 'Stock Item'[stock_item_id] ),
        CALCULATE ( AVERAGE ( Simulation[on_hand_end] ) ) * CALCULATE ( MAX ( 'Stock Item'[last_cost_price] ) )
    )
Sim Purchase Orders = CALCULATE ( COUNTROWS ( Simulation ), Simulation[order_qty] > 0 )
Target Gap = [Sim Fill Rate] - MAX ( Scenario[service_level] )

-- Safety stock what-if (continuous service level slider)
-- Create: Modeling → New parameter → Numeric range "Target SL", 0.80 to 0.995, step 0.005, default 0.95
Safety Stock What-if (units) =
    VAR z = NORM.S.INV ( [Target SL Value] )
    RETURN SUMX ( 'Policy Parameters', z * 'Policy Parameters'[sigma_lt] ) / DISTINCTCOUNT ( 'Policy Parameters'[month_start] )
Safety Stock What-if (value) =
    VAR z = NORM.S.INV ( [Target SL Value] )
    RETURN SUMX ( 'Policy Parameters', z * 'Policy Parameters'[sigma_lt] * RELATED ( 'Stock Item'[last_cost_price] ) )
           / DISTINCTCOUNT ( 'Policy Parameters'[month_start] )
-- use with a slicer on Scenario[lt_scenario] (one lead-time assumption at a time; ignore scenario 13)
```

Calculation group (Model view → Calculation groups, Power BI Desktop 2023+): `Time Intelligence` with items
`Current = SELECTEDMEASURE()`, `YTD = CALCULATE(SELECTEDMEASURE(), DATESYTD('Date'[date]))`,
`PY = CALCULATE(SELECTEDMEASURE(), SAMEPERIODLASTYEAR('Date'[date]))`,
`YoY % = DIVIDE(SELECTEDMEASURE() - [PY item], [PY item])` (write PY inline).

## 4. Pages

1. **S&OP overview**: cards: Revenue, Gross Margin %, Units Ordered, Unit Fill Rate, On-Time Delivery %; line: monthly units vs SEAS forecast; KPI trend table by year.
2. **Demand & forecast**: WAPE / Bias by model (Forecast Accuracy table, calibration vs test); actual vs forecast line for a selected SKU; ABC-XYZ matrix (count SKUs, revenue share); seasonal index column chart.
3. **Policy simulation**: scatter: x = Sim Avg Inventory Value, y = Sim Fill Rate, one point per scenario, colour = lt_scenario, shape = target_type (the efficient frontier); exclude scenario 13 from the scatter (ERP, off-scale); table of 17 scenarios with Target Gap; daily on-hand line for a selected SKU + scenario (drill-through from table).
4. **Planning-parameter audit**: declared vs actual lead time (Lead Time Audit), excess inventory value by supplier / stock group; what-if slider Target SL → Safety Stock What-if.
5. **Customer service**: Service Monthly trends (fill rate down, order-to-delivery days up); backorder share by stock group; top backorder SKUs.
6. **Data quality & ETL**: DQ Results (latest run_id), severity colour; Load Log (rows, duration, status).

Drill-through: page "SKU detail" (filter stock_item_id) reachable from pages 2, 3, 5.
RLS demo: role "Clothing planner" with filter `'Stock Item'[primary_stock_group] = "Clothing"`.
